# 기술 문서 원칙 (수강생 본인 규칙)

`/portfolio-update`가 `CLAUDE.md`를 템플릿으로 덮어써도 남도록 여기에 둡니다.
`포트폴리오 피드백 통합본.md`(로컬 전용)와 강사님 지적(Asana 11-21)에서 정한 것으로, 세션을 나눌 때마다 인계 배경에 되풀이하던 목록입니다. 새 세션은 따로 듣지 않아도 이 규칙을 지킵니다. 말투는 `writing-style.md`를 따릅니다.

## 쓰는 내용
- **사실만 씁니다.** 약점·하소연 문장은 빼고, 그 안의 사실은 남깁니다.
- **프로젝트는 서로 따로 씁니다.** 다른 작품과 잇는 문장("첫 게임에서 배운 것을 …")은 넣지 않습니다.
- 출처 표기는 필요한 곳에만 짧게 둡니다.
- 재구성의 기준은 **흐름**입니다. 같은 기능이 여러 장에 흩어지지 않게 기능 장으로 모읍니다.

## 사실 확인
- **건우 님이 기억으로 말한 코드 이야기(구조·패턴·수치)는 코드와 대조한 뒤 넣습니다.** 코드와 다르면 넣지 않고, 다른 점을 보여 주며 묻습니다. (11-23: "이벤트 구독 패턴"이라고 답했지만 코드는 interface 구조였고, 마감 전날 발견됨)
- 기간(기획/개발 따로)·발표일·역할·도움받은 부분은 각 기술문서 1장의 기본 정보 표를 기준으로 씁니다. 표와 다른 말을 들으면 표부터 고칠지 묻습니다.
- 문서에 없는 숫자·사실은 지어내지 않고 빈칸이나 ❓로 남깁니다.

## 표시와 표기
- Claude가 쓴 문장에는 `<!-- ✏️ -->`를 답니다. 지운 문장은 숨김 주석으로 남기고, 기존 숨김 주석은 지우지 않습니다.
- "리팩터링"이 아니라 **"리팩토링"**으로 씁니다.
- 결정 표 양식: `> **결정 대상**` + `| | [A] | **[B] ✓** |` + "**[B]를 골랐습니다.**"
- 클래스 표기는 "역할 (이름)" 순서입니다. mermaid에서는 `class X["역할 (X)"]`로 씁니다.
- 코드 머리줄은 `// 파일.메서드 (○~○행 발췌)` 형식입니다. 행 번호를 확인할 수 없으면 비워 둡니다.

## 단계별 작업
- 장·절 단위로 나눠 고칠 때는 **보여 주기 전에 스스로 이 규칙과 통합본 기준으로 다시 읽고 사실을 대조**합니다. 건우 님은 장마다 확인만 합니다.
