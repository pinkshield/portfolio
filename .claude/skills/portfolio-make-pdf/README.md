# /portfolio-make-pdf — 포트폴리오 PDF 만들기 스킬 사용 안내

포트폴리오 문서(`index.html`)를 **제출용 A4 PDF**(`<이름>-포트폴리오.pdf`)로 만들어 주는 Claude Code 스킬입니다.
그냥 브라우저에서 인쇄(Ctrl+P)하면 휴대폰 폭 배치로 찍히거나 겹치는 문제가 생기는데, 이 스킬은
페이지를 **넓은 화면 배치 그대로 A4에 맞게 줄여** 찍고, 결과를 **자동·눈으로 점검**한 뒤 문제가 없을 때만 확정합니다.
mac·Windows 모두에서 동작합니다(이 템플릿을 포크해 각자 고쳐 쓰는 페이지에도 맞춰 씁니다).

---

## 1. 무엇을 해 주나

- **화면 배치를 따르는 PDF** — 넓은 화면의 단 나눔·그림 자리·간격 그대로. 큰 절은 새 쪽에서, 흰 종이.
- **점검 후 확정** — 페이지 오류·깨진 그림·`localhost` 주소·쪽 수·겹침·잘림·빈 쪽·글씨 크기·줄바꿈을 보고, 통과한 파일만 레포에 둡니다.
- **글씨 다듬기** — 본문 9pt 이상을 목표로 키우되 줄바꿈이 과해지지 않는 데까지. 이미 잘 보이는 큰 글은 그대로, 글씨 사이 크기 비율은 원본에서 크게 벌어지지 않게, 캡션은 모두 같은 크기.
- **배치 다듬기** — 쪽에 빈 곳이 많거나 칸이 좁으면 PDF 전용 배치 후보(가로↔세로, 3×2↔2×3, 칸 비율, 2+1 카드는 1열 등)를 직접 시험해 보고 **전·후를 보여 준 뒤 확인받고** 반영합니다.
- **링크** — 화면의 버튼·글자 링크를 PDF에서도 그대로(누르면 열림). 링크 주소는 GitHub Pages 배포 주소로.
- **그림 압축** — 만드는 동안만 그림을 줄여 PDF를 가볍게(원본 파일은 그대로). 예: 10MB → 2.5MB.
- **장 표지(선택)** — 원본에 흐린 대표 이미지 배경이 있으면 PDF에서도 쪽 끝까지 흐린 배경 + 어두운 글씨로.

## 2. 지키는 규칙

스킬은 PDF를 만들고 다듬을 때 아래 규칙을 지킵니다. 배치를 바꾸는 후보를 시험할 때도 이 규칙을 깨는 후보는 고르지 않습니다.

### 일하는 방식

| 규칙 | 내용 |
|---|---|
| 점검을 통과한 파일만 확정 | 미리 만든 PDF(레포 밖 임시 폴더)를 점검하고, 통과하면 **그 파일 그대로** `<이름>-포트폴리오.pdf`로 옮깁니다. 다시 만들어 바꿔치지 않습니다. 문제가 있으면 확정하지 않고 몇 쪽에서 무엇이 왜 깨졌는지 알려 줍니다 |
| 배치를 바꾸는 건 확인받고 | 배치 다듬기는 후보를 직접 시험한 뒤 **전·후 숫자와 쪽 그림을 보여 주고 확인받은 것만** `theme/pdf.css`에 씁니다(점검 대상 설정 줄은 PDF 모양을 바꾸지 않아 확인 없이 씀) |
| 렌더러는 요청할 때만 | `index.html`·`assets/` 같은 페이지 코드는 사용자가 요청할 때만 고칩니다. PDF 손질은 `theme/pdf.css`에만 합니다 |
| 내용은 소스에서 | 사실·설명·그림이 틀리면 PDF가 아니라 기술 문서·`profile.md`를 고치고 `/portfolio-build`로 안내합니다 |
| 원본은 그대로 | 그림 압축은 PDF를 만드는 동안에만 합니다. `src/`의 그림 파일은 바꾸지 않습니다 |
| 커밋은 요청할 때만 | PDF·`theme/pdf.css`를 만들어도 커밋·푸시는 하지 않습니다 |
| 시험은 정해진 만큼 | 배치 후보 시험은 한 번에 8번 이내. 문제가 있는 절만, 가장 작은 변경부터 |

### 배치

| 규칙 | 내용 |
|---|---|
| 화면 배치를 따름 | 넓은 화면 배치(기본 1040px)를 A4에 맞게 줄여 찍어, 단 나눔·순서·그림 쪽·간격이 화면과 같습니다 |
| 흰 종이, 큰 절은 새 쪽에서 | 쪽 위 여백은 종이 기준(mm)이라 글씨 크기를 바꿔도 그대로입니다. 새 쪽에서 시작하는 절은 위 안쪽 여백 0 |
| 링크는 버튼 그대로 | 화면의 링크 버튼·글자 링크를 PDF에서도 그대로 둡니다(누르면 열림, 밑줄·↗ 화살표도 화면처럼). 주소를 글로 풀어 쓰는 것은 **맨 아래 연락처 링크 모음만**. 링크는 배포 주소로 바꾸고, `localhost`가 남으면 확정하지 않습니다 |
| 그림 옆 글은 그림 기준 가운데 | 캡션을 뺀 **그림 자체**의 세로 가운데에 글을 둡니다. 캡션은 그림 아래 따로 |
| 쪼개지는 묶음은 세로로 | 카드 세 장처럼 한 줄에 다 안 들어가 2+1로 쪼개지면 1열로. 길이가 서로 다른 목록(연락처 등)은 나란히 |
| 표가 좁으면 비율을 다시 | 정보 표 칸이 좁아 줄이 많이 꺾이면 그림·표 비율을 30→35→40→45 순서로 시험해, 가장 긴 칸이 4줄 이하이면서 그림이 가장 큰 비율을 고릅니다(대표 그림은 종이 위 90mm 이상) |
| 빈 곳 줄이기 | 쪽 채움이 50% 미만이면 그 절의 배치(3×2↔2×3, 가로↔세로, 칸 비율)를 바꾸거나 다음 절을 이어 붙입니다 — 쪽 수가 늘지 않을 때만 |
| 장 표지(선택) | 흐린 대표 이미지 배경은 쪽 끝까지, 글씨는 어두운 테마로. 흐린 배경은 그림으로 굳혀 **쪽 자체의 배경**으로 칠합니다(절에 칠하면 앞 쪽 아래에 가는 선이 남음). 배경이 밝으면 흰 글씨와 대비(기본 3:1)가 될 때까지 자동으로 어둡게. 글자 그림자·큰 흐린 그림자는 PDF에서 사각형 얼룩이 생겨 쓰지 않습니다 |

### 글씨

| 규칙 | 내용 |
|---|---|
| 본문 9pt를 목표로 키움 | 배치 폭을 40px씩 줄여 가며 가장 큰 글씨를 찾되(화면을 따르는 페이지는 768px 아래로 안 감), **줄바꿈이 과해지지 않는 데까지만** |
| 줄바꿈 한도 | 지금 배치와 비교해 — 큰 글(제목·소개 문장)은 한 줄도 늘면 안 됨 · 본문은 1.5배 이상이면서 두 줄 넘게 늘면 안 됨 · 한두 낱말만 남는 줄이 새로 생기면 안 됨 · 주소가 단어 중간에서 끊기면 안 됨 · 한 줄이어야 할 제목·칩·항목명이 여러 줄이 되면 안 됨 |
| 이미 잘 보이는 글은 그대로 | 화면 비율로 줄였을 때 이미 10pt 이상인 글(이름·한 줄 소개·자기소개 문장·제목·개발 의도 본문 등)은 키우지 않고, 작은 글만 키웁니다. 크기 순서(화면에서 큰 글이 PDF에서도 큼)는 지킵니다 |
| 글씨 사이 비율 유지 | 원본에서 **가장 큰 글**(보통 첫 쪽 이름)을 기준으로, 각 글의 크기 비율이 PDF에서 1.25배 넘게 벌어지거나 좁혀지지 않습니다 |
| 같은 종류는 같은 크기 | 캡션은 모두 같은 크기. 키웠을 때 어느 하나라도 줄이 늘면 줄이 늘지 않는 데까지만 키웁니다 |
| 줄 길이 고르게 | 큰 글은 줄 길이를 고르게 나누고, 본문은 문단 끝에 낱말 하나만 남지 않게 합니다 |
| 인쇄용 크기가 따로 있는 페이지 | 템플릿 기본 배치처럼 인쇄 규칙이 글씨 크기를 따로 정한 페이지는 도구가 알아보고, 축소 없이 그 크기 그대로에서 시작합니다(위 비율 규칙 대신 그 페이지가 정한 크기 순서를 지킴) |

### 점검 기준(요약)

| 항목 | 기준 |
|---|---|
| 페이지 | 오류 없음 · 깨진 그림 없음 · 가로 넘침 없음 |
| 링크 | `localhost` 0곳 |
| 쪽 수 | 잰 값과 같고, 구성이 같으면 이전 PDF와 같음 |
| 파일 크기 | 5 MB 이하 |
| 글씨 | 본문 9pt 목표(8pt 미만은 미달) · 작은 글 7.5pt · 가장 작은 글 7pt 이상(캡션은 줄바꿈 규칙 때문에 작을 수 있음) |
| 종이 위 크기 | 대표 그림 90mm · 기능 그림 55mm · 정보 표 55mm 이상 |
| 쪽 채움 | 마지막 쪽 50% 이상(첫 쪽 40%, 맨 끝 쪽은 예외) |
| 눈 점검 | 겹침·잘림·홀로 남은 제목·빈 그림·남은 어두운 바탕·장 표지 앞 쪽 가는 선·흐린 그림이 없는지 |

## 3. 필요한 것

| | mac | Windows |
|---|---|---|
| Claude Code | 필요 | 필요 |
| Google Chrome(또는 Edge) | 필요 | 필요 |
| 파이썬 3.8 이상 | 보통 이미 있음(`python3 --version`) | [python.org](https://www.python.org/downloads/)에서 설치(설치 화면의 **py launcher** 포함). `py -3 --version`으로 확인 |
| 그림 압축 | 기본으로 됨(sips) | 기본으로 됨(Chrome 안에서). Pillow를 깔면 Pillow로: `py -3 -m pip install pillow` |
| 인터넷 | 페이지가 글꼴·라이브러리를 CDN에서 받으므로 필요 | 같음 + 쪽 그림 점검에 pdf.js를 받음 |

환경마다 도구가 알맞은 방식을 고릅니다. 지금 컴퓨터에서 무엇을 고르는지 보려면:

```bash
python3 tools/make-pdf.py --env
```

Windows라면:

```bash
py -3 tools/make-pdf.py --env
```

## 4. 설치 (내 포트폴리오 레포에 넣기)

필요한 것은 **두 군데**뿐입니다: 스킬 폴더 `.claude/skills/portfolio-make-pdf/`와 도구 `tools/make-pdf.py`.

### 방법 A — 공유한 사람의 레포에서 git으로 받기 (추천)

내 포트폴리오 레포 폴더에서(터미널·Git Bash·PowerShell 모두 같음):

```bash
git remote add pdfskill https://github.com/keeeery/portfolio.git
```

```bash
git fetch pdfskill main
```

```bash
git checkout pdfskill/main -- .claude/skills/portfolio-make-pdf tools/make-pdf.py
```

```bash
git remote remove pdfskill
```

- 다른 파일(내 `index.html`·`data/`·`src/` 등)은 건드리지 않고 이 두 곳만 가져옵니다.
- 주소(`https://github.com/keeeery/portfolio.git`)는 이 스킬을 공유한 사람의 레포입니다. 다른 사람에게서 받았다면 그 사람 레포 주소로 바꿉니다.
- 새 버전을 받을 때도 같은 명령을 다시 실행하면 됩니다.

### 방법 B — 압축 파일로 받기

공유받은 압축 파일을 내 레포 맨 위 폴더에 풀어, 아래 두 곳이 생기면 됩니다.

```
내 레포/
├── .claude/skills/portfolio-make-pdf/   (SKILL.md · variants.md · pdf.css.template · raster.swift · README.md)
└── tools/make-pdf.py
```

> `.claude` 폴더는 이름이 점으로 시작해 탐색기·Finder에서 숨겨져 보일 수 있습니다(mac: Finder에서 ⌘+Shift+. / Windows: 탐색기 [보기] → [숨긴 항목]).

### 설치 뒤

Claude Code를 다시 열면 `/portfolio-make-pdf`가 명령 목록에 보입니다.
원하면 `CLAUDE.md`의 명령 표에 한 줄 추가해 두세요(없어도 동작합니다).

> **`/portfolio-update` 주의:** 템플릿 업데이트가 스킬 폴더를 템플릿 원본으로 바꾸면 이 스킬(템플릿에 없는 스킬)이 지워질 수 있습니다.
> 업데이트 뒤 `/portfolio-make-pdf`가 안 보이면 위 설치를 한 번 더 하세요. 내 설정이 담긴 `theme/pdf.css`는 업데이트가 건드리지 않습니다.

## 5. 사용 방법

Claude Code에서:

| 입력 | 하는 일 |
|---|---|
| `/portfolio-make-pdf` | 바뀐 것이 있으면 PDF를 만들어 점검 → 문제없으면 확정 |
| `/portfolio-make-pdf 다시` | 바뀐 것이 없어도 다시 만들어 점검 → 확정 |
| `/portfolio-make-pdf 미리보기` | 점검까지만(확정 안 함) |
| `/portfolio-make-pdf 배치 유지` | 배치 다듬기 없이 지금 배치로(글씨·빈 곳은 보고만) |
| `/portfolio-make-pdf 준비` | 처음 준비(내 페이지 읽고 설정 줄 채우기)만 다시 |

말로 해도 됩니다: "PDF 다시 만들어 줘", "PDF 글씨가 너무 작아", "기타 프로젝트 쪽이 비어 보여", "위 여백 20mm로 해 줘" 등.

**처음 한 번은** 스킬이 내 `index.html`을 읽고 준비합니다:
1. `theme/pdf.css`(PDF 전용 배치 손질 파일)를 시작본으로 만들고, 내 페이지에 맞춘 **설정 줄**(점검 대상 선택자 등)을 채웁니다.
2. 내 페이지가 어느 갈래인지 봅니다.
   - **화면 크기를 따르는 인쇄**(직접 바꾼 레이아웃에 흔함)면 넓은 배치를 줄여 찍습니다.
   - **인쇄용 글씨 크기를 따로 정한 인쇄**(템플릿 기본 배치)면 A4 폭 그대로 찍습니다.
3. 기본 인쇄 규칙이 PDF 규칙과 어긋나면 고칠 조각을 시험해 보여 주고 **확인받아** `theme/pdf.css`에 넣습니다.
   예: 링크 버튼이 사라짐, 주소를 글로 풀어 씀, 캡션 위치.

그다음부터는 만들 때마다 같은 순서입니다:
1. 미리 만들기(레포 밖 임시 폴더)
2. 자동 점검
3. 쪽 그림으로 눈 점검
4. 필요하면 배치 다듬기(전·후 보여 주고 확인)
5. 확정: 레포 맨 위 `<이름>-포트폴리오.pdf`. 커밋은 요청할 때만 합니다.

### 결과물

- `<이름>-포트폴리오.pdf` — 레포 맨 위. 이름은 `profile.md`의 이름(= `data/portfolio.json`의 `profile.name`).
- `theme/pdf.css` — 내 PDF 설정. 직접 고쳐도 됩니다.
- 배포(GitHub Pages)에 올리려면 이 둘을 커밋·푸시하세요. Claude에게 "커밋해 줘"라고 해도 됩니다.

## 6. `theme/pdf.css` 설정 줄

파일 맨 위의 `/* 키: 값 */` 줄은 도구가 읽는 설정입니다. 숫자만 바꾸고 `/portfolio-make-pdf 다시`를 실행하면 됩니다.

| 설정 | 기본 | 뜻 |
|---|---|---|
| `layout-px` | 1040 | 이 폭의 화면 배치를 A4에 맞게 줄여 찍음. **작을수록 글씨가 큼**(1040 ≈ 66% · 900 ≈ 76% · 780 ≈ 88%, 688 = 축소 없음). 화면을 따르는 페이지는 768 아래로 내리지 않음 |
| `keep-readable` | 10pt | 화면 비율로 이미 이 크기 이상인 글(이름·소개 문장·제목 등)은 키우지 않음. `off`면 모두 똑같이 |
| `ratio-limit` | 1.25 | 원본에서 가장 큰 글 대비 각 글의 크기 비율이 이 배수까지만 달라짐. `off`면 끔 |
| `backdrop-contrast` | 3 | 흐린 배경 위 흰 글씨의 최소 대비(클수록 배경이 어두워짐) |
| `@page { margin-top: 20mm; }` | 페이지 설정 | 쪽 위 여백(종이 기준) |
| `page-root` · `caption` · `backdrop` · `check-…` | — | 내 페이지에 맞춘 점검·처리 대상(처음 준비 때 스킬이 채움) |

그 아래 `@media print { … }` 안의 규칙들은 배치 다듬기로 넣은 PDF 전용 배치입니다. 각 줄 위 주석에 무엇을 위한 것인지 적혀 있습니다.
지우면 그 손질만 빠집니다. 파일을 비우면 페이지 기본 인쇄 배치로 돌아갑니다.

## 7. [PDF로 저장] 버튼 연결 (선택)

템플릿의 [PDF로 저장] 버튼은 브라우저 인쇄 창을 엽니다. 확정한 PDF를 바로 열고 받게 하려면 Claude에게
"**PDF로 저장 버튼을 확정 PDF로 연결해 줘**"라고 하세요(페이지 렌더러를 고치는 일이라 요청할 때만 합니다). 바뀌는 동작은 이렇습니다:

- 레포 맨 위에 `<이름>-포트폴리오.pdf`가 있는지 HEAD 요청으로 확인 → 있으면 버튼이 [새 탭에서 열기]·[파일로 받기](같은 이름으로 저장), 없으면 예전처럼 인쇄 창.
- 파일 이름 규칙은 도구와 같아야 합니다: `<이름에서 \/:*?"<>| 를 뺀 것>-포트폴리오.pdf`(NFC), 주소에는 `encodeURIComponent`로.

> 템플릿 렌더러 파일(`assets/…`·`classic.html` 등)을 고치면 `/portfolio-update`가 덮어쓸 수 있습니다. 직접 만든 레이아웃(`/portfolio-custom`)의 `index.html`에 넣는 편이 안전합니다.

## 8. 문제 해결

| 증상 | 할 일 |
|---|---|
| "Chrome을 찾지 못했습니다" | Chrome을 설치하거나 `--chrome "<chrome.exe 경로>"`를 붙여 달라고 하세요 |
| Windows에서 `python3`이 없다고 함 | `py -3`을 씁니다(스킬이 알아서 고름). 그래도 없으면 python.org에서 설치 |
| 한글 파일 이름이 깨짐 | 도구는 UTF-8로 출력합니다. 오래된 콘솔이면 `chcp 65001` 뒤 다시 |
| 쪽 그림 점검을 못 함(Windows, 인터넷 없음) | pdf.js를 받지 못한 것. 스킬이 PDF를 보내 주면 직접 열어 확인 |
| PDF에 `localhost` 주소가 남음 | 페이지에 글로 적힌 주소일 수 있음 — 스킬이 그 위치를 알려 줌. 배포 주소가 다르면 "배포 주소는 …"이라고 알려 주세요 |
| 글씨가 너무 작음/큼 | "PDF 글씨 키워 줘" 또는 `theme/pdf.css`의 `layout-px` 조절 |
| 받은 PDF가 예전 것 | 확정 PDF를 커밋·푸시해야 배포 페이지의 버튼이 새 파일을 줍니다 |

## 9. 이 스킬을 다시 공유하려면

- 내 레포에 위 두 곳(`.claude/skills/portfolio-make-pdf/`, `tools/make-pdf.py`)이 커밋·푸시돼 있으면, 다른 사람은 설치 방법 A의 주소만 내 레포로 바꿔 받으면 됩니다.
- 내 `theme/pdf.css`는 **내 페이지 전용**이라 공유하지 않습니다. 받는 사람은 처음 준비 때 자기 페이지에 맞춰 새로 만듭니다.
- 모두가 `/portfolio-update`로 받게 하려면 템플릿 원본 레포에 제안(Pull Request)하는 방법도 있습니다(강사님 확인 필요).
