## 2. 클로드 Pro에서 진행할 사실 보강 포인트 (3곳)

문서 내 `[사실 보강 예정: ...]` 태그가 달린 아래 3곳을 사용자와의 질의응답 또는 프로젝트 원본 기록(Git 커밋, 아사나, 시연 영상) 대조를 통해 채워 주세요.

### ① 1-3 개발 환경 · 링크 — GitHub 저장소 공개 여부
- **위치**: `1-3. 개발 환경 · 링크` 표 내 `GitHub` 항목
- **현재 상태**: `` `KooHoo-Dev/3rd-TeamProject-HS` [사실 보강 예정: 현재 저장소 공개 전환 여부 확인 및 링크 상태 업데이트] ``
- **보강 가이드**: 해당 저장소가 Public으로 전환되었는지 확인하여 하이퍼링크를 걸거나, 팀 정책상 비공개 유지라면 포트폴리오 열람자를 위한 안내 문구(예: 코드 발췌본 수록 안내)로 정리하세요.

### ② 7-1 AI와 나눈 일 — AI 결과물 검증 방식 및 잘 된 사례
- **위치**: `7-1. AI와 나눈 일 — AI는 코드 생성, 저는 구조 설계` 중 `잘 된 점과 확인 방식` 항목
- **현재 상태**: `[사실 보강 예정: AI가 생성한 코드의 동작을 에디터(기즈모·로그 등)로 어떻게 검증했는지, 그리고 AI 협업 과정에서 특히 잘 작동했던 프롬프트나 역할 분담 사례 1~2가지 보강]`
- **보강 가이드**:
  - AI가 짜 준 `BoxCast` 범위, 저항도 감소 수치, `CancellationToken` 취소 타이밍 등을 Unity 에디터에서 어떤 방식(예: `OnDrawGizmos` 시각화, 상태 전이 `Debug.Log`, 2인 에디터/빌드 동시 테스트 등)으로 검증했는지 구체화하세요.
  - 이전 작업 인계 메모에 남아 있던 "AI 협업에서 잘 된 점"에 대해 사용자 본인의 실제 경험(예: 인터페이스 규약 먼저 정해주고 구현 맡기기 등)을 2~3문장으로 보강하세요.

### ③ 8-2 트러블슈팅 ③ — 해양 지뢰 넉백 작동 확인 기록
- **위치**: `8-2. 트러블슈팅` → `③ 해양 지뢰 접촉 시 플레이어 넉백 미작동`의 `결과` 항목
- **현재 상태**: `[사실 보강 예정: 지뢰 폭발 및 넉백 작동이 실제 빌드/영상에서 정상 확인된 장면이나 테스트 기록 보강]`
- **보강 가이드**: `linearVelocity` 직접 지정(`5655008`, 09-02) 이후 2차·3차 빌드 테스트 또는 시연 영상(YouTube)에서 지뢰 폭발 및 플레이어 넉백이 정상 작동한 확인 근거(예: 3차 빌드 테스트 지뢰 관련 버그 0건, 혹은 시연 영상 내 특정 구간/스테이지 테스트 기록)를 확인해 한 줄 보강하세요.
