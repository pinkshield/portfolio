# /portfolio-make-pdf — 점검한 뒤 PDF 확정

인자: `$ARGUMENTS`
- 비어 있음: 바뀐 것이 있으면 만들어 점검 → 문제없으면 확정
- `미리보기`: 점검까지만(확정하지 않음)
- `다시`: 바뀐 것이 없어도 다시 만들어 점검 → 확정
- `배치 유지`: 4-1(배치 다듬기)을 건너뜀 — 글씨·빈 곳은 보고만
- `준비`: 0(처음 쓰는 페이지 준비)만 다시 함

> 수강생이 만든 스킬입니다(템플릿에 없음). `/portfolio-update`가 스킬 폴더를 템플릿으로 바꾸면 사라질 수 있어, 업데이트 뒤에는 같은 방법으로 다시 받아 오세요(사용 안내: 이 폴더의 `README.md`).

## 무엇이 어디 있나

| 파일 | 역할 |
|---|---|
| `tools/make-pdf.py` | PDF 도구(파이썬 표준 라이브러리 + Chrome). 만들기·점검(`--report`)·후보 시험(`--css`)·줄바꿈 비교(`--against`)·쪽 그림(`--pages`)·확정(`--finalize`)·확정 이름(`--print-name`)·환경(`--env`) |
| `theme/pdf.css` | **PDF 전용 배치 손질** — 인쇄에만 덧씌움(도구가 넣으므로 페이지가 불러오지 않아도 됨). 맨 위 설정 줄(`/* 키: 값 */`)은 도구가 읽음. 수강생의 파일 — 배치를 바꾸는 줄은 **확인받은 것만** 씀 |
| `<이름>-포트폴리오.pdf` | 확정된 PDF(레포 맨 위). 이름은 `data/portfolio.json`의 `profile.name` |
| 이 폴더 `pdf.css.template` | 처음 쓸 때 `theme/pdf.css`의 시작본(설정 줄 설명 포함) |
| 이 폴더 `variants.md` | 배치 다듬기 후보 — 어느 페이지에나 쓰는 **패턴**과, 그 패턴을 한 페이지에 적용한 **예시 조각** |
| 이 폴더 `raster.swift` | mac에서 쪽 그림을 PDFKit(미리보기 앱과 같은 엔진)으로 그릴 때 도구가 씀 |
| 이 폴더 `README.md` | 사람이 읽는 사용 안내 · 공유 방법 · [PDF로 저장] 버튼 연결 |

### 실행 준비 (mac·Windows)
- **파이썬:** mac·리눅스는 `python3`, Windows는 `py -3`(없으면 `python`). 아래 명령의 `$PY`는 그중 되는 것. 처음에 `$PY --version`으로 고릅니다(3.8 이상).
- **Chrome:** Google Chrome(또는 Edge). 못 찾으면 `--chrome "<경로>"`.
- `$PY -I tools/make-pdf.py --env`로 이 컴퓨터에서 고른 방식을 봅니다. 도구가 **환경에 맞춰 고르며, mac은 mac 방식 그대로**입니다:

| | mac | Windows |
|---|---|---|
| Chrome 연결 | 파이프 | 로컬 포트(WebSocket) — 결과 PDF는 같음 |
| 그림 압축 | Pillow 있으면 Pillow, 없으면 `sips` | Pillow 있으면 Pillow, 없으면 Chrome 안에서(canvas) |
| 쪽 그림(`--pages`) | PDFKit(`raster.swift`) | Chrome 안의 pdf.js(인터넷 필요) |

- 미리 만든 파일은 **세션 스크래치 폴더**(시스템 프롬프트에 있으면 그곳, 없으면 OS 임시 폴더)의 `pdf-preview/`에 둡니다. 레포 안에 만들지 않습니다. 아래 `$P`가 그 폴더입니다.
- 셸이 달라도 되게, 복사·이름 정하기는 도구 옵션으로 합니다(`--finalize`, `--print-name`). `cp`·`swift`를 직접 부르지 않습니다.

## PDF 규칙 (어느 페이지에나 — 도구·`theme/pdf.css`가 지킴, 후보를 만들 때도 깨지 않음)

**배치**
1. **화면 배치를 따릅니다.** 페이지를 넓은 화면 폭(`layout-px`, 기본 1040)으로 배치해 A4에 맞게 줄여 찍습니다 — 단 나눔·순서·그림 쪽·간격이 화면과 같습니다. 다듬기는 문제가 있는 절만, 가장 작은 변경부터.
2. **흰 종이, 큰 절은 새 쪽에서.** 쪽 위 여백은 종이 기준(mm, `@page { margin-top }`)이라 배치 폭을 바꿔도 그대로. 새 쪽에서 시작하는 절은 위 안쪽 여백 0.
3. **링크는 화면처럼 버튼·글자 링크 그대로**(PDF에서 누르면 열림, 밑줄·↗ 화살표도 화면처럼). 주소를 글로 풀어 쓰는 것은 **맨 아래 연락처 링크 모음만**. 링크는 배포 주소로(도구가 바꿈 — `localhost` 남으면 확정 안 함).
4. **그림 옆 글은 캡션을 뺀 그림 자체의 세로 가운데**(캡션은 그림 아래 따로).
5. **세 개짜리처럼 한 줄에 다 안 들어가 2+1로 쪼개지는 묶음은 세로(1열)로**, 길이가 서로 다른 목록(연락처 등)은 나란히. 표가 좁아 줄이 많이 꺾이면 그림·표 비율을 다시 정함(그림은 종이 위 90mm 이상).
6. **장 표지**(선택): 원본에 흐린 대표 이미지 배경이 있는 절은 PDF에서도 쪽 끝까지 흐린 배경 + 어두운 글씨로 둘 수 있음. 흐린 배경은 도구가 그림으로 굳혀 **쪽(@page) 배경**으로 칠함(절 배경은 앞 쪽 아래에 가는 선을 남김), 밝으면 `backdrop-contrast`(기본 3:1)까지 자동으로 어둡게. 글자 그림자·큰 흐린 그림자는 PDF에서 사각형 얼룩이라 쓰지 않음.

**글씨**
7. **본문 9pt 이상을 목표로 적극적으로 키우되, 줄바꿈이 과해지지 않는 데까지.** (지금 배치와 비교: 큰 글(20px 이상)은 한 줄도 늘면 안 됨 · 본문은 1.5배 이상이면서 두 줄 넘게 늘면 안 됨 · 한두 낱말만 남는 줄이 새로 생기면 안 됨 · 주소가 단어 중간에서 끊기면 안 됨)
8. **이미 잘 보이는 글은 키우지 않습니다**(`keep-readable`, 기본 10pt): 화면 비율로 줄였을 때 이미 이 크기 이상인 글(이름·한 줄 소개·자기소개 문장·제목·개발 의도 본문 등)은 그대로, 작은 글만 키움 — 크기 순서 유지.
9. **글씨 사이 비율이 원본에서 크게 벌어지지 않습니다**(`ratio-limit`, 기본 1.25): 원본에서 **가장 큰 글** 대비 각 글의 비율이 PDF에서 ×1.25·÷1.25 안.
10. **같은 종류의 글은 같은 크기**(`caption`, 기본 `figcaption`): 캡션은 모두 같은 크기, 키워서 어느 하나라도 줄이 늘면 늘지 않는 데까지만.
11. 큰 글은 줄 길이를 고르게(`text-wrap: balance`), 본문은 문단 끝 외톨이 낱말을 피함(`text-wrap: pretty`).

`CLAUDE.md`의 **반드시 지킬 원칙**도 따릅니다. 특히:
- **점검을 통과한 파일만 확정합니다.** 확정 = 점검한 그 파일을 그대로 옮기기(`--finalize`). 다시 만들지 않습니다. 문제가 있으면 확정하지 않습니다.
- **렌더러(`index.html` 등)는 사용자가 요청할 때만** 고칩니다. PDF 손질은 `theme/pdf.css`에. 내용(사실·설명·그림)이 틀리면 소스 → `/portfolio-build`.
- `theme/pdf.css`에서 **배치를 바꾸는 줄은 확인받은 뒤에만** 씁니다(점검 대상 설정 줄은 확인 없이 써도 됨 — 결과 PDF를 바꾸지 않음).
- 커밋은 사용자가 요청할 때만 합니다.

## 0. 처음 쓰는 페이지 준비 (`theme/pdf.css`가 없거나 설정 줄이 없을 때, 또는 인자 `준비`)

이 스킬은 페이지마다 구조가 달라도 쓰도록 만들었습니다. 처음에는 그 페이지를 읽고 맞춥니다.

1. `$PY -I tools/make-pdf.py --env`로 파이썬·Chrome·방식을 확인합니다. Chrome이 없으면 설치 안내 후 멈춤.
2. `theme/pdf.css`가 없으면 이 폴더의 `pdf.css.template`을 복사해 만듭니다.
3. `index.html`(포트폴리오 문서)을 읽고 **설정 줄**을 채웁니다(이 줄들은 점검·처리 대상만 정하고 결과 PDF 모양은 바꾸지 않음):

| 설정 줄 | 무엇 | 찾는 법 |
|---|---|---|
| `/* page-root: #root */` | 내용을 담은 맨 바깥 요소 | React면 보통 `#root`, 아니면 `main`·`body` |
| `/* caption: figcaption */` | 같은 크기로 묶을 캡션 | 그림 설명 요소(대개 `figcaption`) |
| `/* backdrop: … */` | 흐린 대표 이미지 배경 묶음(장 표지용) | CSS `filter: blur(…)`가 걸린 그림의 부모. 없으면 비움(도구가 흐린 그림을 스스로 찾음) |
| `/* check-single-line: … */` | 한 줄이어야 할 제목·칩·항목명(기본 `h1, h2, h3, dt, .chip`에 더함) | 카드 제목·기능 제목·영문 머리말 등의 클래스 |
| `/* check-table-cell: … */` · `/* check-table-box: … */` | 프로젝트 정보 표의 값 칸 · 표 전체 | 정보 표(장르·기간·환경…)의 `dd`·그 칸 |
| `/* check-cover-image: … */` · `/* check-feature-image: … */` | 대표 그림 · 기능 그림 | 그 그림 상자의 클래스 |

4. **이 페이지는 어느 갈래인지:** 한 번 미리 만들어(2) `layout.print_vs_screen.median`을 봅니다(도구가 알림도 띄움).
   - **≈ 1(0.9~1.1) — 인쇄가 화면 크기를 따르는 페이지:** 위 규칙 그대로(배치 폭 1040에서 시작해 줄여 가며 글씨를 키움, 768 아래로는 안 감).
   - **1에서 멀다 — 인쇄 규칙이 글씨 크기를 따로 정한 페이지**(템플릿 기본 배치가 대개 이쪽, A4 폭용 pt 글씨): 넓은 배치로 줄여 찍으면 글씨가 지나치게 작아집니다.
     설정 줄을 `/* layout-px: 688 */`(축소 없이 A4 폭 그대로) · `/* keep-readable: off */` · `/* ratio-limit: off */`로 시작하고, 글씨·빈 곳은 4-1에서 조각(글씨 크기·칸 비율)으로 다듬습니다.
     이 갈래에서는 규칙 8·9 대신 **인쇄 규칙이 정한 크기 순서를 지키는 것**이 기준이고, 화면 배치와 꼭 같을 필요는 없습니다(그 페이지 인쇄 규칙이 이미 PDF용 배치).
   - 사용자가 "화면처럼"을 원하면 첫 갈래로 바꾸되, 그 페이지 인쇄 규칙의 글씨 크기 지정을 `theme/pdf.css`에서 되돌리는 조각이 필요합니다(확인받고).
5. **기본 인쇄 규칙 확인:** 그 페이지의 `@media print`가 위 PDF 규칙 1~6을 지키는지 봅니다(흰 종이·버튼 숨김 여부·주소 목록·쪽 나눔·캡션 위치 등).
   어긋난 것은 **`theme/pdf.css`에 넣을 조각**으로 만들어(variants.md의 "P. 처음 준비 패턴") 2~4처럼 시험한 뒤 보여 주고 확인받아 씁니다. 렌더러는 고치지 않습니다.
6. **[PDF로 저장] 버튼 연결(선택):** 페이지의 버튼이 아직 인쇄 창을 열면, 확정 PDF를 열고 받게 바꿀 수 있습니다. 렌더러를 고치는 일이라 **사용자가 원할 때만** `README.md`의 "버튼 연결"대로 합니다.

## 1. 바뀐 것 확인

```bash
PDF="$($PY -I tools/make-pdf.py --print-name)"
git log -1 --format='%h %ci' -- "$PDF"
git diff --stat <그 커밋> -- index.html profile.md data src theme assets
git status --porcelain -- index.html profile.md data src theme assets "*.pdf"
```

- `$PDF`가 없거나 커밋된 적 없음 → 처음 만들기. 그 뒤로 바뀐 것이 없고 `$PDF`가 있음 → "최신입니다"(인자 `다시`면 진행).
- 다른 이름의 `*-포트폴리오.pdf`·`portfolio.pdf`가 있으면(이름을 바꾼 경우) 확정할 때 옛 파일을 지울지 묻습니다(커밋된 파일이면 `git mv`).
- 기술 문서 `.md`나 `profile.md`는 바뀌었는데 `data/`가 그대로면 "`/portfolio-build`를 먼저 할까요?"라고 묻습니다.

## 2. 미리 만들기 (덮어쓰지 않음)

```bash
$PY -I tools/make-pdf.py --out "$P/portfolio.pdf" --report "$P/report.json" --pages "$P/pages"
```

직전에 확정한 PDF의 점검 결과가 있으면 `--against <그 report.json>`을 붙여 줄바꿈 변화를 봅니다. 배포 주소가 git remote로 짐작한 것과 다르면 `--base <주소>`(사용자가 알려 준 주소만).

## 3. 자동 점검 — `report.json`

| 항목 | 통과 기준 | 어긋나면 |
|---|---|---|
| `ready` · `page.ready` | `yes` 또는 `generic`(템플릿의 `PFPage`가 없는 페이지) | 다시 한 번, 그래도면 문제로 보고 |
| `page.errors` · `page.images.broken` · `page.overflowX` | 비어 있음 · 비어 있음 · 0 | 그대로 보고(그림 경로는 기술 문서·`data`) |
| `local_links` | 비어 있음 | 확정하지 않음 |
| `pages` | `layout.est_pages`와 같음, 이전 PDF와 같은 구성이면 같은 쪽 수 | 넘쳐서 쪽이 늘어난 것 → 4에서 그 쪽 확인 |
| `mb` | 5 MB 이하 | `env.compress`가 `none`인지, 큰 그림이 새로 왔는지 |
| `layout.fonts.body_pt` | **목표 9pt 이상**(8pt 미만은 미달) | 4-1 |
| `layout.fonts.small_pt` · `min_pt` | 7.5pt · 7pt 이상(캡션은 규칙 10 때문에 작을 수 있음 — 보고에 적음) | 4-1 |
| `layout.keep_readable.ratio_dev_max` | `ratio_limit` 이하 | 캡션처럼 줄바꿈 규칙이 우선한 글인지 `ratio_dev_at`으로 확인 |
| `layout.wrap` | `url_broken` 0 · `table.max` 4줄 이하 · `single_multi`가 지금보다 늘지 않음 | 4-1(그 칸을 넓히는 후보) |
| `grew`(비교했을 때) | `big`·`body`·`short` 모두 0 | 4-1 |
| `layout.images_mm` | 대표 그림 90mm · 기능 그림 55mm · 정보 표 55mm 이상(설정한 것만) | 비율·그림 칸 후보 |
| `layout.chunks[].last_fill` | 마지막 쪽 채움 50% 이상(머리 덩어리 40%, 맨 끝 쪽은 예외) · 여러 쪽짜리가 30% 미만이면 넘친 것 | 4-1 |
| `layout.print_vs_screen.median` | 0.9~1.1이면 화면을 따르는 페이지, 아니면 인쇄용 크기를 따로 정한 페이지(0의 4) | 갈래에 맞게 설정 줄 |
| `layout.backdrops` | 장 표지를 쓰면 절마다 하나씩, `page: true`, 쪽당 50KB 이하 | 배경이 검기만 하면 그림을 못 읽은 것 |

글씨·빈 곳·줄바꿈 기준은 확정을 막지 않고 4-1로 갑니다(인자 `배치 유지`면 보고만). 나머지는 어긋나면 확정하지 않습니다.

## 4. 눈으로 점검 — 쪽 그림

`$P/pages/sheet.png`(모든 쪽)를 먼저 보고, 이상해 보이는 쪽과 **바뀐 곳이 있는 쪽 · 마지막 쪽**은 `pNN.png`를 크게 봅니다.

| 볼 것 | 깨진 모습 |
|---|---|
| 겹침 · 잘림 | 글·그림이 겹쳐 그려짐 · 쪽 아래에서 잘리거나 한 줄만 다음 쪽으로 |
| 홀로 남음 | 절 제목만 쪽 끝에 · 거의 빈 쪽 |
| 그림 · 색 | 회색 빈 칸 · 흰 종이여야 할 쪽에 어두운 바탕 · 장 표지 쪽에 흰 테두리·사각형 얼룩 · **장 표지 바로 앞 쪽 맨 아래 가는 선** |
| 규칙 | 위 PDF 규칙 1~11(버튼이 버튼으로, 주소 풀어쓰기는 맨 아래만, 캡션 뺀 그림 기준 정렬 …) |
| 주소 · 화질 | 배포 주소(`localhost` 없음) · 그림이 뭉개지지 않음 |

쪽 그림을 못 만들면(인터넷이 없어 pdf.js를 못 받는 등) 미리 만든 PDF를 사용자에게 보내(SendUserFile) 위 표대로 봐 달라고 합니다.

## 4-1. 배치 다듬기 — 글씨가 작거나 빈 곳·줄바꿈 문제가 있을 때

2에서 만든 `report.json`을 **비교 기준**으로 둡니다. 시험마다 `--against "$P/report.json"`.

1. **무엇을 고칠지:** 어긋난 항목마다 원인 절을 짚습니다(예: "본문 6.9pt — 배치 폭 1040에서 66%라서", "정보 표 52mm — 대표 그림에 밀려서", "연락처 주소 6곳 끊김 — LINK 칸이 좁아서", "카드 2+1 — 3장이 한 줄에 안 들어가서").
2. **후보 만들기:** `variants.md`의 패턴을 그 페이지 선택자로 옮깁니다. 후보 하나 = 지금 `theme/pdf.css` + 조각, `$P/try-N.css`.
   - **글씨:** (화면을 따르는 페이지) 배치 폭을 40px씩 줄여(…→ 900 → 860 → 820 → 780, **768 아래로는 안 감**) 줄바꿈 한도 안의 가장 큰 글씨. (인쇄용 크기를 따로 정한 페이지) 배치 폭은 688로 두고 본문·작은 글 선택자의 글씨 크기를 조각으로 키움. 한도를 넘긴 글이 한두 곳뿐이면 그 칸을 넓히는 조각을 더해 같은 폭으로 다시. 배치 폭을 줄이면 한 쪽에 들어가는 양이 줄어 그림 칸도 맞춤.
   - **빈 곳:** 그 절의 배치 바꾸기(3×2↔2×3, 가로↔세로, 칸 비율) 또는 다음 절을 이어 붙이기(쪽 수가 늘지 않을 때만).
   - **표·칸이 좁음:** 칸 비율을 30 → 35 → 40 → 45 순서로, 가장 긴 칸 4줄 이하이면서 그림이 가장 큰 비율.
3. **시험하기:**
   ```bash
   $PY -I tools/make-pdf.py --css "$P/try-1.css" --against "$P/report.json" --out "$P/try-1.pdf" --report "$P/try-1.json" --pages "$P/try-1"
   ```
   하나씩 시험한 뒤 좋아진 것끼리 묶어 한 번 더. **모두 합쳐 8번 이내.**
4. **고르기:** 3의 다른 항목이 모두 통과 · 쪽 수가 늘지 않음(늘면 보여 주고 사용자가 고름) · 글씨가 작아지지 않음 · `grew` 모두 0 · 크기 기준 통과 · 4의 눈 점검 통과. 그중 어긋난 항목이 가장 많이 풀린 것, 비슷하면 화면 배치에서 덜 벗어난 것.
5. **확인받기:** 숫자 표(쪽 수 · 본문/작은 글 pt · 쪽 채움 · 주소 끊김 · 표 가장 긴 칸 · 그림·표 mm, 전 → 후)와 바꾼 것을 쉬운 말로, 두 `sheet.png`를 보내고 AskUserQuestion: [이 배치로 적용(추천)] · [지금 배치 유지].
6. **적용하면** 후보 내용을 `theme/pdf.css`에 씁니다(조각마다 무엇을 위한 것인지 한 줄 주석). 그다음 **2부터 다시**(`--css` 없이) 해서 숫자가 시험 때와 같은지 확인하고 5로. **유지하면** 지금 배치로 5로 가고 남은 문제를 보고에 적음.
